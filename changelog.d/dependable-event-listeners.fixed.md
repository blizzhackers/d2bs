- **Dependable event listeners.** Listeners can remove or clear any listener, including themselves, during an event, with `removeEventListener()`, `clearEvent()` or `clearAllEvents()`, and the game keeps running. A listener that throws has its error printed at once (with its file and line when it throws an `Error`), the event's other listeners still run, and a key, chat line, packet or hook click is blocked only by a listener that returned `true`; `keyupblocker` listeners run for the key-ups D2BS dispatches and can block them, as `keydownblocker` listeners do for key-downs (with the console prompt open, only the Alt key reaches key listeners, and their verdict is not used). An error thrown inside a `setTimeout()` or `setInterval()` callback is reported the moment it happens, the script carries on, and an interval keeps running; timers of a script that has finished release their resources at once. After `clearEvent()`, a script stops counting as a listener for that event, so broadcasts skip it and blocking events such as packets, keys and chat lines don't wait on it, and scripts can add and remove listeners while game, key and packet events arrive. Scripts can end or reload while game events, broadcasts and console commands are being delivered (short-lived scripts with DisableCache on included) and the game keeps running, and a console command (a console line, a `.exec` chat command or a copydata 0x1337 line) whose value has no text form, such as `Object.create(null)`, reports its error and leaves the console running, and the game too unless `QuitOnError` is set in game. When memory runs out, `addEventListener()`, `setTimeout()` and `setInterval()` fail at that call as other calls do: the script stops there, or, inside an event listener, the rest of that event is skipped.
