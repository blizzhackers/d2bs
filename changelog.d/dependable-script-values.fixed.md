- **Dependable script values and arguments.** Script functions return the value their documentation names every time: `unit.getItems()` returns an empty array when there is nothing to list, `getSkillByName()` finds a skill's id by name in any letter case and returns `undefined` for an unknown name, `screenToAutomap({x, y})` and `automapToScreen({x, y})` return the converted point like their two-number forms and leave the argument as it was, `getStat(-2)` lists a stat's several charged or chance-to-cast skills as a gap-free array, `checkCollision()` keeps reporting a unit that has left the game as blocked, and unit, item, control, exit, preset unit, folder, profile, script and screen hook members return their usual empty result for a unit that has left the game, a control whose screen is gone or an object of another kind, so the script keeps running (a unit's properties keep the last value read while it was in the game). `getDistance()` also measures to any object with `x` and `y`, `new Image()` and `image.location` accept any image name under the script folder every time and refuse a name that points outside it or is too long to load, `getUnit()`, `getNext()` and `me.getItem()` take a name of any length, `unit.getNext(classId)` always filters by that class id, `moveNPC()` takes any number for its coordinates, control `state` and edit-box `cursorpos` read back what the script set, and `Folder.create()` names the whole path in its "not found" error. `moveNPC()`, `include()`, `isIncluded()`, `loadMpq()`, `Folder.create()`, `me.move()` and `me.overhead()` report a bad argument where they are called, as do `unit.getState()`, `control.setText()`, `addEventListener()`, `removeEventListener()` and `clearEvent()` when a required argument is missing, while `acceptTrade()`, `getCursorType()`, `getMouseCoords()`, `js_strict()`, `stop()`, `item.shop()` and `me.setSkill()` act only on the arguments they are given. A script that runs out of memory while D2BS reads a name, text or image path stops there, and the game keeps running.
