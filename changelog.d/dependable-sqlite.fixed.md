- **Dependable SQLite databases and statements.** SQLite errors carry SQLite's full message, `%` signs and long names included, and `sqlite_memusage()` returns the bytes SQLite holds. `new SQLite(name)` opens the database unless a boolean second argument says otherwise, and a refused name or a database that can't be opened releases its memory; `db.open()` opens a database created with `autoOpen` set to false and reopens one after `db.close()`; `db.close()` leaves `isOpen` false so later queries throw "Database must first be opened!"; and `lastRowId` and `changes` read 0 on a database that isn't open, with `lastRowId` returning row ids above 2147483647 (exact up to 2^53). `getObject()` returns the current row as an object, the same one until the statement moves on, and frees it once the statement moves on, closes or is collected; `skip(n)` stops at the end of the results and returns how many rows it moved past; and `ready` reads false after `go()`, `reset()`, `close()` or the database's `close()`. Strings passed to `SQLite.query()` and `DBStatement.bind()` keep their text until the statement runs, in every database, including UTF-8 database files. A DBStatement keeps the game running when it is closed twice or used after `close()`, `go()` or its database's `close()`, SQLite and DBStatement members return their usual empty result when called on an object of another kind, and a script that reaches its memory limit while D2BS runs SQL, binds a value or builds a result stops at that call, as it would anywhere else, and the game keeps running.
