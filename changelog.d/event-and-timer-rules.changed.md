- **Event and timer rules.** A listener added while an event is being delivered runs from the next event, and a listener removed then is not called for that event if it has not run yet (unless it is added again before its turn). Once a script is stopped (or, for an in-game script, its game ends), no further listener of the event starts, and with `QuitOnError` set, a listener or timer callback that throws in game exits the game when it throws. `script.send()` reaches a script that is still starting (just loaded or reloaded) or paused, and copies nothing, so nothing can throw, for a script that has ended or, once started, has no `scriptmsg` listener. A paused script's messages and timers wait for `resume()` (or, in game, run while it waits inside a game call such as a skill change), and each pending timer runs once then. When at least one running script listens, `scriptBroadcast()` throws for a value that can't be copied (a function, or a game object such as a Unit), as `script.send()` does, so such a value reaches no script; getters on broadcast values run once however many scripts listen. `setTimeout()` and `setInterval()` throw an error the script can catch, right where they are called, when the callback is not a function, the delay is missing or not a number, or Windows could not create or set the timer, and a successful call always returns a timer id; `clearTimeout()` and `clearInterval()` do nothing for undefined or null, cut a fraction to a whole id (1.5 cancels timer 1), and throw an error the script can catch for any value that is not a number.
