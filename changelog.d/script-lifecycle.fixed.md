- **Dependable script starts, reloads and script objects.** A script with a syntax error, whether loaded with `load()`, typed as a `load` console command or set as the starter script, prints its error and a "failed to start" line and ends while the game and your other scripts keep running, and a script that runs out of memory as it starts prints the "failed to start" line too. Loading a script that is already running, from a script, the console or a chat command, ends the running copy and starts the new one once that copy has ended or half a second has passed, without holding up the caller, and `getScript()`, `getScripts()`, stopping all scripts and leaving a game reach the new copy, including when a script loads its own file, and `stop()` on a script that has not started yet keeps it from running; with `DisableCache=false` a running copy that is replaced gives its memory back, and loading a file that does not exist leaves nothing behind. Values passed to `load()` are freed once the new script's main function returns, so the memory they use is released when the script finishes, and `load()` with no file name, or one that isn't a string or is too long, throws an error the script can catch. A script object from `getScript()` or `getScripts()` that outlives its script reports `running` as false and lets `pause()`, `resume()`, `stop()`, `send()` and `join()` return at once, so it only ever acts on its own script, and `getScript(true).join()` throws "A script can't join itself" where it is called, so the script can catch it and carry on. A message sent with `script.send()` reaches a script waiting in `delay()` right away, an empty script file loads or includes as an empty script, and a console script whose main function returns stays loaded while the game keeps running.
